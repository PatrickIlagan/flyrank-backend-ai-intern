# Week 2 — Build Your First CRUD API

## Goals
- Understand HTTP fundamentals, the request–response cycle, REST verbs, and standard HTTP status codes.
- Build an in-memory Task Management CRUD API step-by-step across 6 structured stages.
- Test and document endpoints using `curl` and interactive Swagger UI (`/docs`).
- Maintain a professional Git commit history (at least 6 stage commits) and write clear developer-facing documentation.

## Tasks
- [ ] **Stage 0: Hello Server** — Initialize project environment and start a server listening on localhost.
- [ ] **Stage 1: Root & Health Endpoints** — Add API descriptor at `GET /` and health check at `GET /health`.
- [ ] **Stage 2: Read Endpoints (List & Single)** — Store in-memory tasks, serve `GET /tasks`, and serve `GET /tasks/:id` with `404` handling.
- [ ] **Stage 3: Create with Validation** — Implement `POST /tasks` returning `201 Created` and validate missing/empty title with `400 Bad Request`.
- [ ] **Stage 4: Update & Delete (Full CRUD)** — Implement `PUT /tasks/:id` and `DELETE /tasks/:id` returning `204 No Content`.
- [ ] **Stage 5: Swagger UI** — Set up interactive OpenAPI docs at `/docs` and verify the full CRUD cycle via UI.
- [ ] **Stage 6: Publish & Documentation** — Complete README with run instructions, endpoint table, sample `curl -i` output, and Swagger screenshot.
- [ ] **Optional Extras & AI Rematch** — Add query filters/search/stats, run the mortality experiment, and complete Stage 7 AI Rematch diff.
